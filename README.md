### 1. 과제 소개

> 입력 패턴과 필터를 곱하고 더하는 MAC 연산을 구현하고, Cross와 X를 구분하는 과제.

사람은 그림을 보고 십자가와 X를 쉽게 구분하지만, 프로그램에서는 그림을 숫자 배열로 바꿔 계산해야 합니다. 이번 과제에서는 같은 위치의 값을 곱한 뒤 모두 더해 점수를 구하고, 두 필터 중 점수가 높은 쪽으로 판정하도록 만들었습니다.

3×3 배열을 직접 입력하는 기능과 제공된 `data.json`을 분석하는 기능을 구현했습니다. 크기별 연산 시간을 측정하고, 2차원 배열을 1차원으로 바꿨을 때의 차이도 비교했습니다.

주요 실습 내용

- 리스트를 이용한 2차원 필터 및 패턴 저장
- 이중 반복문을 이용한 MAC(Multiply-Accumulate) 연산 구현
- 행·열 개수와 숫자 입력 검증 및 재입력 처리
- JSON 키에서 크기를 읽어 해당 필터 선택
- 라벨 정규화와 epsilon 기반 동점 처리
- 3×3, 5×5, 13×13, 25×25 크기별 성능 측정
- 1차원 배열 변환 전후의 성능 비교
- 크기 N에 따른 Cross·X 패턴 자동 생성

이 문서는 현재 코드와 제공된 데이터의 실제 실행 결과를 기준으로 작성했습니다. 안내문의 출력 예시는 참고용이므로, 결과 표에는 이번에 실행한 점수와 판정을 정리했습니다.

### 3. 실습 및 실행 방법

#### 프로그램 실행

터미널에서 과제 폴더로 이동한 뒤 실행합니다.

```powershell
cd KDJ-E1-3
py main.py
```

`py` 명령이 없는 환경에서는 Python 3.8 이상으로 연결된 `python main.py` 또는 `python3 main.py`를 사용합니다. 외부 라이브러리가 없어 `pip install` 과정은 필요하지 않습니다.

현재 작업 폴더의 검증용 Python으로 실행하려면 다음 명령을 사용합니다.

```powershell
& .\.runtime\python\python.exe main.py
```

#### 메뉴 및 기능 목록

| 번호 | 화면 이름 | 기능 |
| --- | --- | --- |
| 1 | 사용자 입력 (3×3) | 필터 A·B와 패턴 입력, MAC 점수·판정·연산 시간 출력 |
| 2 | data.json 분석 | 크기별 필터 로드, 패턴 검증, PASS/FAIL 및 전체 결과 출력 |
| 3 | 패턴 생성기 | N을 입력받아 Cross·X 생성, 생성한 배열로 성능 측정 |

메뉴를 선택하면 해당 기능을 실행하고 종료합니다. 다른 기능을 확인하려면 프로그램을 다시 실행하면 됩니다.

#### 사용자 입력 예시

1번을 선택한 뒤 필터 A, 필터 B, 패턴 순서로 입력합니다. 각 배열은 총 3줄이며, 한 줄에 숫자 3개를 공백으로 구분합니다.

```text
필터 A        필터 B        패턴
0 1 0         1 0 1         1 0 1
1 1 1         0 1 0         0 1 0
0 1 0         1 0 1         1 0 1
```

위 입력에서는 다음 결과를 확인할 수 있습니다. 연산 시간은 실행할 때마다 달라집니다.

```text
A 점수: 1.0
B 점수: 5.0
판정: B
```

각 배열의 첫 줄에 `cross` 또는 `x`를 입력하면 해당 모양의 3×3 배열을 자동 생성합니다. 따라서 필터 A에 `cross`, 필터 B와 패턴에 각각 `x`를 입력해도 같은 결과를 확인할 수 있습니다.

#### 입력 및 예외 처리

- 입력 앞뒤 공백을 제거하고 메뉴 번호와 숫자를 확인합니다.
- 열 개수가 맞지 않거나 숫자로 바꿀 수 없는 값은 안내 후 해당 행을 다시 입력받습니다.
- NaN과 무한대는 계산에 사용하지 않습니다.
- JSON의 패턴 크기, 필수 항목 또는 라벨이 잘못되면 해당 케이스를 FAIL로 처리하고 다음 패턴을 분석합니다.
- 필터에 오류가 있으면 해당 필터를 사용하는 패턴에 실패 원인을 표시합니다.
- 파일이 없거나 JSON을 읽을 수 없으면 오류 내용을 안내합니다.
- Ctrl+C 또는 입력 스트림 종료가 발생하면 안내 후 종료합니다.

| `read_matrix()` | 행별 숫자 입력과 재입력 처리 |

#### 데이터 파일 설명 — data.json

저장 위치는 실행한 터미널의 현재 폴더가 아닌 **`main.py`와 같은 폴더의 `data.json`**입니다. 다른 폴더에서 프로그램 경로를 지정해 실행해도 같은 파일을 읽습니다.

함께 넣은 파일은 제공된 원본의 복사본이며, 원본과 SHA-256 해시가 같은 것을 확인했습니다. 필터 값이나 expected는 수정하지 않았습니다.

| 키 | 역할 |
| --- | --- |
| `filters` | 크기별 필터를 담는 객체 |
| `filters.size_N` | N×N 크기의 Cross·X 필터 쌍 |
| `cross` / `x` | 각 필터의 2차원 숫자 배열 |
| `patterns` | 분석할 패턴을 담는 객체 |
| `size_N_idx` | 패턴의 크기 N과 식별 번호를 담은 키 |
| `input` | N×N 입력 패턴 |
| `expected` | 비교할 정답 라벨 |

예를 들어 `size_13_2`는 13×13 패턴이므로 `filters.size_13`의 필터를 사용합니다. 배열은 `matrix[i][j]` 형태로 값을 읽고 수정할 수 있습니다.

라벨은 다음 기준으로 통일했습니다.

| 입력 표기 | 프로그램 내부 표기 |
| --- | --- |
| `cross`, `Cross`, `+` | `Cross` |
| `x`, `X` | `X` |

MAC는 같은 위치의 값을 곱하고 모두 더하는 계산입니다. 신경망에서도 이런 계산이 반복되므로, 여러 MAC 연산을 병렬로 처리할 수 있는 하드웨어가 연산 속도에 영향을 줍니다. 이번 프로그램에서는 반복문으로 계산 원리를 확인했습니다.

### 5. 트러블슈팅

#### 1. 필터 키와 expected의 표기가 다른 문제

- 문제: 필터에는 `cross`, `x`가 사용되지만 expected에는 `+`, `x`가 들어 있습니다.
- 원인: 같은 의미라도 문자열을 그대로 비교하면 서로 다른 값으로 판단합니다.
- 조치: `normalize_label()`에서 Cross와 X로 통일한 뒤 출력과 PASS/FAIL 비교에 사용했습니다.
- 현재 확인: expected가 `+`인 패턴도 Cross로 비교되며, 표기 차이로 인한 실패는 발생하지 않았습니다.

#### 2. 소수점 계산의 작은 차이가 판정을 바꾸는 문제

- 문제: `size_5_1`의 두 점수가 0.9와 0.8999999999999999로 나왔습니다.
- 원인: 0.1 같은 소수를 이진 부동소수점으로 정확히 표현하지 못해, 값을 반복해서 더할 때 작은 오차가 생깁니다.
- 조치: 두 점수 차이가 `1e-9`보다 작으면 동점으로 처리했습니다. 차이가 정확히 `1e-9`이면 큰 점수를 선택합니다.
- 현재 확인: 동점에 해당하는 세 케이스가 UNDECIDED로 출력되고, expected와 비교해 FAIL로 집계되었습니다.

> 소수점 아래 차이가 보인다고 바로 큰 점수를 선택하면 계산 오차가 판정을 결정할 수 있었습니다. 이번에는 과제에서 정한 허용오차 기준을 적용했습니다.

#### 3. 잘못된 패턴 하나 때문에 분석이 중단될 수 있는 문제

- 문제: JSON에 크기가 맞지 않는 배열이나 잘못된 키가 들어올 수 있습니다.
- 조치: 키 형식과 행·열 크기를 검사하고, 개별 케이스의 오류를 처리한 뒤 다음 항목으로 넘어가도록 구성했습니다.
- 현재 확인: 행이 부족한 패턴과 잘못된 키를 넣은 테스트에서 해당 항목만 FAIL이 되었고, 뒤의 정상 패턴은 계속 분석되었습니다.

#### 4. 성능 비교에 입출력과 변환 시간이 섞이는 문제

- 문제: 파일 읽기와 화면 출력까지 측정하면 MAC 연산 시간만 비교하기 어렵습니다.
- 조치: 입력 준비와 1차원 변환을 먼저 끝낸 뒤, 연산 함수 호출을 반복하는 구간만 측정했습니다. 두 방식의 입력과 반복 횟수도 같게 맞췄습니다.
- 현재 확인: 각 크기에 대해 2차원·1차원 방식의 평균 시간과 MAC 횟수를 출력하며, 두 방식의 계산 결과도 비교합니다.

### 6. 결과 리포트

#### 제공 데이터 분석 결과

원본 데이터에는 5×5, 13×13, 25×25 패턴이 각각 2개씩 들어 있습니다. 실행 결과는 **총 6개, 통과 3개, 실패 3개**였습니다.

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
| --- | ---: | ---: | --- | --- | --- |
| size_5_1 | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.700000000000008 | X | X | PASS |
| size_13_2 | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

#### 실패 원인 분석

실패한 세 케이스는 배열 크기나 라벨을 잘못 읽어서 발생한 경우는 아니었습니다.
필터와 패턴의 크기는 모두 일치했고, expected도 표준 라벨로 변환되었습니다.
세 케이스 모두 두 필터의 점수가 수학적으로 같다는 공통점이 있었습니다.
`size_5_1`은 Cross 점수가 0.9이고, X 점수는 0.1을 9번 더한 값입니다.
`size_13_2`는 0.3을 25번 더한 값과 7.5를 비교하는 구조입니다.
`size_25_1`은 Cross 점수 4.9와 0.1을 49번 더한 값을 비교합니다.
실수 계산에서는 누적 과정의 오차로 두 점수가 조금씩 다르게 출력되었습니다.
하지만 세 케이스 모두 차이가 `1e-9`보다 작아 UNDECIDED로 처리했습니다.
expected에는 각각 X, Cross, X가 지정되어 있으므로 최종 결과는 FAIL입니다.
따라서 이번 실패는 MAC 반복문의 계산 오류보다 동점 데이터와 정답 라벨의 관계에서 원인을 찾을 수 있습니다.
라벨 정규화는 표기 차이로 생길 실패를 막아 주지만, 동점인 패턴의 정답까지 결정해 주지는 않습니다.
통과 수를 늘리려고 epsilon을 줄이면 부동소수점 오차에 따라 판정이 달라질 수 있어 기준을 유지했습니다.
데이터를 보완한다면 동점을 정답으로 인정할지 정하거나, 두 점수가 충분히 벌어지도록 입력과 필터를 조정하는 방법이 있습니다.
이번에는 제공된 값과 과제의 동점 처리 기준을 그대로 적용했습니다.

| 구분 | 확인 내용 |
| --- | --- |
| 데이터·스키마 | 제공 데이터의 크기와 키는 정상. 의도적으로 넣은 오류는 해당 케이스에서 처리 |
| 계산 로직 | 3×3 예제 점수와 2차원·1차원 MAC 결과 일치 확인 |
| 수치 비교 | 작은 점수 차이를 epsilon으로 비교하고 동점 3개를 UNDECIDED로 처리 |
| expected 비교 | UNDECIDED는 Cross·X와 다르므로 세 케이스 모두 FAIL |

#### 성능 측정 결과

Windows, Python 3.12.8에서 실행한 측정값입니다. 각 방식은 준비 실행을 5회 한 뒤 1,000회 반복한 평균을 구했습니다. 파일 읽기, 출력, 입력 검증과 1차원 변환 시간은 제외했습니다.

3×3은 자동 생성한 Cross를 사용했습니다. 나머지는 각 크기의 첫 번째 패턴과 제공된 Cross 필터를 사용했으며, 같은 행의 두 방식에는 동일한 입력을 적용했습니다.

| 크기 | 2차원 평균(ms) | 1차원 평균(ms) | MAC 횟수(N²) | 속도비(2D/1D) |
| --- | ---: | ---: | ---: | ---: |
| 3×3 | 0.000815 | 0.000439 | 9 | 1.85 |
| 5×5 | 0.001703 | 0.001127 | 25 | 1.51 |
| 13×13 | 0.008814 | 0.005901 | 169 | 1.49 |
| 25×25 | 0.034772 | 0.023506 | 625 | 1.48 |

속도비는 2차원 시간을 1차원 시간으로 나눈 값입니다. 1보다 크면 1차원 방식이 더 빠르게 측정된 것입니다. 짧은 연산을 측정하므로 CPU 상태나 백그라운드 작업에 따라 다시 실행했을 때 수치는 달라질 수 있습니다.

#### 시간 복잡도 및 최적화 분석

2차원 방식은 N개 행마다 N개 열을 방문하므로 반복 횟수가 N²입니다.
표의 MAC 횟수는 필터 하나에 대한 곱셈과 누적 덧셈의 쌍을 센 값입니다.
Cross와 X를 모두 계산하는 판정 한 번에는 `2N²`번의 MAC이 필요합니다.
필터가 두 개로 고정되어 있으므로 시간 복잡도는 O(N²)로 정리할 수 있습니다.
한 변의 길이가 두 배가 되면 연산량은 네 배가 됩니다.
3×3에서 25×25로 커지면 MAC 횟수는 9회에서 625회로 약 69.4배 늘어납니다.
측정한 2차원 시간은 약 42.7배 늘었으며, 작은 입력에서는 함수 호출과 반복문 준비 비용의 비중이 커서 연산량 비율과 정확히 같지는 않았습니다.
복잡도의 근거는 모든 원소를 한 번씩 방문하는 반복문 구조이며, 측정 결과에서도 크기가 커질수록 시간이 늘어나는 것을 확인했습니다.
1차원 방식은 길이가 N²인 리스트를 순회하므로 역시 O(N²)입니다.
이번에는 약 1.48~1.85배 빨랐지만, 인덱스 접근과 반복문 비용을 줄인 것이므로 복잡도 자체가 바뀐 것은 아닙니다.
Python 리스트는 숫자를 가리키는 참조를 저장하므로, 1차원 변환만으로 모든 숫자가 연속된 실수 메모리에 저장되는 것은 아닙니다.
변환에도 O(N²) 시간과 추가 공간이 들어가므로 한 번만 계산할 때는 변환 비용까지 고려해야 합니다.
배열 저장 공간은 O(N²)이고, MAC 함수에서 점수를 누적하는 데 필요한 추가 공간은 O(1)입니다.
